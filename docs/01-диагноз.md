# Диагноз текущего кода

Источники: `PipeBuild_merged1.lsp` (~12 200 строк) и `PoperSwift.lsp` (~4 900 строк).

## Два движка на одной полилинии

Одна LWPOLYLINE несёт XData `PIPEBLD` и `SWIFT_POPER`. Реактор POPER (`:vlr-modified`) вызывает `poper-full-update`. PipeBuild в это время делает `entmod`. Защита — флаги `*poper-updating*` / `*pb-rebuilding*`, которые ставятся и снимаются в разных функциях.

`pb-update-section` на любое обновление: удаляет 5 дочерних профилей, слой, аннотации, зоны → строит всё заново → 6× `poper-full-update` → `pc-build-all` → объёмы → план.

Поперечник сейчас **не строится** без `CHILD:` пяти продольников. Это ложная зависимость: геометрия траншеи считается из трубы + TIN.

## Хвосты линий

Владение через `entlast` → `entnext` → список handle в `CS_CHILD:`. Что не попало в список — остаётся. Что попало лишнее — убивается. Штриховка, DIM, объекты на чужом слое (`PoperSwift_Table`) дырявят этот список.

Блок AutoCAD закрывает это: содержимое сечения = определение блока, снаружи один INSERT.

## Медленно

Полный delete+rebuild, выгрузка всей TIN в LISP (`pc-surf-tri`), `ssget "X"` по чертежу, повторные проходы реактора, COM на каждую трубу.

## Настройки в четырёх местах

XData PIPEBLD, XData SWIFT_POPER, NOD (`CS_SEC_X_END` на весь чертёж), `setenv`. Нет одного корня «Участок».

## Что не берём как основу

- **pb4** — модули + INSERT, но без поперечников и POPER. Идеи да, код как ядро нет.
- **PipeProfile** — «раздел = блок», сидит на монолитах.
- Патчи июля 2026 — симптомы, не архитектура.
